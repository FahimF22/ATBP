% ABSTRACT
% ============================================================
\begin{abstract}
\normalfont
In sequential multi-agent systems built on large language models (LLMs),
each agent passes its intermediate reasoning to the next, so a wrong
claim made early can shape several later decisions before the final
answer appears. Existing rollback, verification, and self-correction
methods detect or reverse errors, but none we found chooses how much
reasoning to replace based on the dependencies between claims. We
propose the Adaptive Targeted Backtracking Protocol (ATBP). ATBP splits
intermediate reasoning into atomic claims, links them in a directed
dependency graph, checks each claim with a hybrid verifier that combines
deterministic arithmetic and grounding checks with an LLM judge, and uses
the result to choose among four recovery actions: isolated claim repair,
dependency-aware branch backtracking, agent-level regeneration, and full
regeneration.

We evaluate ATBP on GSM8K with GPT-4o-mini. All systems start from the
same initial plan, and every model call is logged with its token count.
Under controlled fault injection (16 faults in clean traces), the
verifier found every fault, and ATBP repaired every case with 19--26\%
fewer tokens than full regeneration while rewriting much less of the
accepted reasoning. The later agents, however, also reached the correct
answer without any recovery. On 30 unmodified problems every system
scored 93.3\%. The errors that remained were misreadings of the question
that the verifier did not detect. These small-sample results suggest
that targeted repair is cheap and safe once an error is found, and that
the main obstacles are detecting the errors that matter and testing on
faults the rest of the pipeline cannot absorb.
\end{abstract}

\begin{IEEEkeywords}
\normalfont
Large language models, multi-agent systems, reasoning verification,
fault localization, fault injection, error recovery, backtracking.
\end{IEEEkeywords}

% 1. INTRODUCTION  (general literature)

\section{Introduction}

LLMs are increasingly deployed as agentic systems in which several
agents plan, reason, verify, and act on a shared task. Instead of
producing an answer in one pass, each agent builds on the output of the
previous one. This division of labor helps with complex problems, but it
also lets errors travel. A sequential pipeline can be written as
\[
P \rightarrow A_1 \rightarrow A_2 \rightarrow \cdots
\rightarrow A_n \rightarrow \hat{y},
\]
where $P$ is the input problem, $A_i$ is an agent, and $\hat{y}$ is the
predicted answer. If an early agent states a wrong assumption,
later agents usually accept it as context and derive more conclusions
from it. The final answer can then be wrong even though every later agent
did its own job correctly. Multi-step mathematical reasoning is
especially exposed, because one early arithmetic or interpretation error
invalidates every calculation that follows.

Prior work has attacked this problem through collaboration and
fine-grained verification. These approaches improve an initial answer or
identify questionable reasoning, but leave open how a system should
recover after an error has entered a sequential trace. We review them
briefly here, and Section~\ref{sec:related} covers the closest work in
detail.

\subsection{Making the First Attempt Better}

Much recent work uses several model instances to improve reasoning. Du et al.
let agents propose answers and critique each other, which raises accuracy
on arithmetic and factuality tasks \cite{debate}. AgentBench provides a
broad evaluation of LLMs on interactive agent tasks and exposes
weaknesses in long-horizon decision making and instruction following
\cite{agentbench}. Other work reduces errors passed between agents by
having them ask for clarification when information is unclear
\cite{agentask}. These studies show that coordination between agents
matters. They improve the quality of the first attempt, but say little
about what to do after a wrong claim has already entered the shared
context.

\subsection{Checking Below the Answer Level}

Another line of work verifies reasoning at a finer grain than the whole
answer. FActScore breaks generated text into atomic factual claims and
scores each against a knowledge source \cite{factscore}, and multi-agent
verifiers extend this idea by assigning claim extraction and checking to
separate agents \cite{march}. This work supports our decision to treat
claims, not whole outputs, as the basic unit of checking. It also shows
the remaining difficulty: these methods find faulty pieces, but they do
not decide how much of the surrounding reasoning to redo.

\subsection{Problem Statement and Contribution}

These lines of work leave one question open: once a faulty claim has
been found, how much should be redone? The choices carry different
costs. Repairing one claim is cheap, but it leaves dependent claims
untouched, and those may now be wrong. Regenerating a whole agent output
removes dependent errors but throws away correct claims. Backtracking
along the dependent claims sits between the two, and full regeneration
restarts everything at the highest computational cost. A fixed strategy
cannot suit every fault.

We study the Adaptive Targeted Backtracking Protocol (ATBP), which
chooses a recovery scope after a fault is detected. ATBP represents
reasoning as atomic claims, links them in a directed dependency graph, and
uses verification confidence and graph features to select one of four
recovery scopes (Section~\ref{sec:architecture}). We do not
claim claim verification, dependency graphs, or rollback as new ideas;
ReAgent \cite{reagent} and step-level verification
\cite{processsupervision,tyen} already cover each of them separately.
Our contribution is to combine them into one recovery-scope selection
framework and to evaluate it against fixed recovery strategies under
controlled faults. The study has four objectives, which
Section~\ref{sec:related} turns into three research questions:

\begin{enumerate}
    \item represent reasoning as atomic claims with prerequisite links;
    \item select the recovery scope from verification and dependency
    features;
    \item evaluate recovery on injected claim-level faults;
    \item report accuracy, error cascade, repair success, collateral
    damage, token usage, and latency.
\end{enumerate}

We test ATBP in two settings (Section~\ref{sec:results}). When
faults are injected into clean traces, the verifier finds all of them,
and targeted recovery repairs them at a lower token cost than full
regeneration while changing much less of the accepted reasoning. On
unmodified problems it does not raise accuracy. The later agents already
correct many errors, and the errors that remain are misreadings of the
question that the verifier does not catch.

The rest of the paper is organized as follows.
Section~\ref{sec:related} reviews the work closest to ours, states the
gaps ATBP addresses, and poses our research questions.
Sections~\ref{sec:dataset}--\ref{sec:method}
describe the dataset, architecture, and method.
Sections~\ref{sec:setup}--\ref{sec:metrics} give the experimental setup
and metrics, Section~\ref{sec:results} reports the results, and
Sections~\ref{sec:discussion} and~\ref{sec:conclusion} discuss
limitations and conclude.

\section{Related Work}
\label{sec:related}

This section covers the work that overlaps directly with ATBP. We
follow the questions a recovery system has to answer in order. Is a
step wrong? Where did the error start? How do errors spread, and how
can they be produced under control? Can the model fix itself? What do
existing systems do once an error is found? Each group answers its
question and leaves the next one open, and the last group leads to the
gaps we address. Table~\ref{tab:gap} condenses the argument.

\subsection{Is a Step Wrong? Step-Level Verification and Claim Checking}

Process reward models (PRMs) score intermediate steps instead of only
the final answer. Lightman et al.\ show the value of process supervision
for mathematical reasoning \cite{processsupervision}. Math-Shepherd
constructs step-level reward signals without requiring human labels for
every step \cite{mathshepherd}, while later work studies PRM data
construction and evaluation \cite{prmlessons}. Sadeddine and Suchanek
verify individual steps in deductive reasoning chains
\cite{deductive}.

FG-PRM is particularly relevant because it goes beyond ordinary
step-scoring. It defines six types of hallucination in mathematical
reasoning and automatically creates fine-grained training examples by
injecting hallucinations into otherwise correct reasoning steps. Its
process reward models detect hallucination types at the step level and
rank candidate solutions \cite{fgprm}. This means synthetic step-level
error injection and fine-grained detection are not new contributions
of ATBP. The distinction in our study is the multi-agent setting and
the matched comparison of recovery scopes after a known claim has been
corrupted.

MARCH is another close claim-level verifier. It uses three agents: a
Solver generates an answer, a Proposer decomposes it into independently
checkable claims, and a Checker verifies each claim against retrieved
evidence without seeing the Solver's original answer
\cite{march}. This information asymmetry is intended to reduce
confirmation bias, and the pipeline is trained with multi-agent
reinforcement learning. Unlike ATBP, MARCH focuses on factual
verification in retrieval-augmented generation rather than choosing
how much of a sequential reasoning trace to replace.

Stepwise Verification also uses detected errors to produce targeted
remediation, but it is designed for tutoring rather than recovery in a
sequential multi-agent trace \cite{stepwise}. Taken together, these
methods establish strong prior work in process supervision, synthetic
reasoning-error generation, claim checking, and localized remediation.
The question left for ATBP is whether the dependency structure of a
multi-agent trace can guide the choice between claim repair, agent-level
regeneration, branch backtracking, and full regeneration. In ATBP the
verifier and generator currently use the same local model, so verifier
reliability must be measured rather than assumed.

\subsection{Where Is the Error? Failure Taxonomies and Attribution}

Knowing that a step is wrong is not the same as knowing where the error
started. MAST defines 14 failure modes in three groups (system design,
inter-agent misalignment, and task verification); its associated
MAST-Data collection contains more than 1,600 annotated traces from
seven frameworks \cite{mast}. Who\&When turns the question
into a task: given a failed multi-agent run, name the responsible agent
and the decisive error step. Its authors report that step-level
accuracy stays low, especially on hand-crafted systems
\cite{whowhen}.

RAFFLES attributes faults offline with iterative reasoning. A Judge
proposes a faulty step, and Evaluators check whether the step is wrong,
whether it is the earliest critical error, and whether it causes the
failure. It is evaluated on Who\&When and on mathematical traces from
ReasonEval (MR-GSM8K and MR-MATH-Invalid) \cite{raffles}. Its authors
note that large public benchmarks for fault attribution are scarce, and
suggest synthetic datasets as a remedy. Tyen et al.\ separate two
abilities: finding a reasoning error and correcting it once its location
is given. Models are poor at the first and can do the second
\cite{tyen}.

These approaches mainly address attribution or correction once a trace
has failed. RAFFLES is post-hoc by design, and Tyen et al.\ correct at a
supplied location.
As far as we can tell, none compares recovery scopes or asks which
downstream claims the fault has contaminated. They do support the case
for separate evaluation of localization and correction, and the call for
synthetic fault data supports our controlled injection.

\subsection{How Do Errors Spread, and How Can They Be Produced Under Control?}

AgentAsk groups communication errors between agents into four types
(data gap, signal corruption, referential drift, and capability gap) and
trains a lightweight policy that decides when and whom to ask for
clarification, with reinforcement learning balancing accuracy against
latency and cost. It reports accuracy gains of up to 4.69\% on five
benchmarks, including GSM8K, with overhead under 10\%
\cite{agentask}. It prevents errors at the message boundary; it does not
repair a wrong claim that has already entered the context.

Huang et al.\ study what faulty agents do to a team. AutoTransform
rewrites an agent's profile so that it adds stealthy errors, and
AutoInject inserts errors directly into its messages. They compare
chain, flat, and hierarchical structures on four tasks, including math,
and report that the linear chain is particularly vulnerable. They then
add a Challenger mechanism and an Inspector agent that reviews and
corrects messages, recovering up to 96.4\% of the errors made by faulty
agents \cite{huangres}. This is the closest prior work to our
multi-agent fault-injection setting. Its injection operates at the
message level and its repair is performed by a reviewer agent. It does
not report a matched comparison of claim repair, dependency-branch
backtracking, agent regeneration, and full regeneration from the same
corrupted trace. Our evaluation makes that comparison and records the
injected claim and its dependents.

\subsection{Can the Model Fix Itself? Limits of Self-Correction}

Tyen et al.\ show that correction works when the error location is
supplied. Huang et al.\ show what happens when it is not: LLMs generally
cannot improve their own reasoning without external feedback, and
intrinsic self-correction can reduce accuracy \cite{huang}. Their GPT-3.5
results illustrate this. Standard prompting reached 75.9\% on GSM8K, two
rounds of intrinsic self-correction reached 74.7\%, and correction with
oracle labels reached 84.3\%. Regenerating again is therefore not a
repair in itself. It needs an external signal, which motivates
claim-level verification as the trigger for recovery in ATBP, and it
motivates measuring how much previously accepted reasoning each recovery
changes.

\subsection{What Do Existing Systems Do After an Error? Rollback, Feedback, and Adaptive Refinement}

Three systems act on errors, and all are close to ATBP. ReAgent adds
local and global rollback to a multi-agent framework so that agents can
return to earlier states when their outputs conflict \cite{reagent}. It
was evaluated on knowledge-intensive multi-hop question answering. Its
rollback has a local and a global level, and as far as we can tell it
does not choose a scope using the dependencies between claims.

AgentDebug names error propagation as the main bottleneck in agent
reliability. It traces a failed trajectory to its root cause using a
taxonomy of failure modes, then feeds corrective feedback back to the
agent for another attempt, with gains of up to 26\% relative task
success on ALFWorld, GAIA, and WebShop \cite{agentdebug}. It is the
closest system in spirit, since it locates the cause and recovers. Its
recovery is feedback followed by a new attempt on agentic benchmarks,
and as far as we can tell it does not select among repair scopes from
the dependency structure of the trace, nor does it target multi-step
arithmetic.

MAgICoRe applies coarse-to-fine iterative refinement and spends extra
reasoning effort on selected parts of a task \cite{magicore}. It decides
where to put effort, but not which previously generated claims must be
replaced once an error is confirmed, and it does not track claim
dependencies. ATBP therefore does not present rollback or feedback as
new; it asks which of several recovery scopes to use.

\subsection{Research Gaps and Our Approach}
\label{sec:gaps}

Taken together, the reviewed work can detect wrong steps, attribute
faults, inject errors, and in some settings provide remediation or
rollback. The gap motivating ATBP is narrower: how to select the scope
of recovery in a sequential multi-agent trace using claim dependencies.
The following four gaps define the questions tested in this study.

\begin{enumerate}
    \item \textbf{No dependency-based scope selection.} Rollback and
    feedback methods \cite{reagent,agentdebug} provide recovery
    mechanisms, adaptive refinement \cite{magicore} allocates effort
    without tracking claim prerequisites, and PRMs and claim verifiers
    \cite{processsupervision,mathshepherd,fgprm,march} primarily detect
    or score errors rather than select a recovery action. The reviewed
    methods do not select among claim repair, agent regeneration, branch
    backtracking, and full regeneration using the prerequisite structure
    of a trace.

    \item \textbf{No downstream-aware localization and repair.}
    Fault attribution \cite{raffles,whowhen} and known-location
    correction \cite{tyen} treat the faulty step on its own and do not
    ask which dependent claims must be reconsidered.

    \item \textbf{No matched comparison of recovery scopes in
    sequential multi-agent traces.} Prior work already injects
    hallucinations into individual mathematical reasoning steps to
    train fine-grained detectors \cite{fgprm}, and studies message-level
    faults in multi-agent collaboration \cite{huangres}. These are
    important precedents. The remaining question is different: how do
    claim repair, agent-level regeneration, dependency-branch
    backtracking, and full regeneration compare when they start from
    the same corrupted sequential multi-agent trace, with the injected
    claim and its expected dependents recorded? The evaluation in this
    paper tests that setting.

    \item \textbf{No shared recovery-specific evaluation protocol.}
    Existing studies use different tasks, fault definitions, and outcome
    measures. The GSM8K results in Table~\ref{tab:literature} provide
    context, but they are not matched comparisons with our results
    \cite{debate,huang}. We therefore evaluate error cascade, repair
    success, and collateral damage under one controlled protocol rather
    than claiming that earlier models or baselines are generally weak.
\end{enumerate}

The model choices in close prior work also differ from ours. MARCH
trains Llama-3.1-8B-Instruct and Qwen3-8B \cite{march}, and RAFFLES
evaluates Llama-3.3-70B-Instruct, gpt-oss-20b, and Claude Sonnet 4
\cite{raffles}. We run our experiments with GPT-4o-mini through the OpenAI
API, a small and inexpensive model that is already strong on GSM8K.

ATBP is designed to address these gaps. First, it selects the recovery
scope from verification results, dependency depth, downstream impact,
and the share of the plan a repair would touch. Second, our controlled
evaluation corrupts single claims in otherwise clean GSM8K traces,
records each fault's location and dependents, and runs every recovery
scope on the same corrupted input. Third, we report three recovery
metrics, the Error Cascade Rate (ECR), Repair Success Rate (RSR), and
Collateral Damage Rate (CDR), together with token usage and model time.

We originally aimed for accuracy above 90\% on GSM8K, compared with the
85.0\% reported for multi-agent debate with ChatGPT \cite{debate}.
GPT-4o-mini already passes this on our sample without any recovery, so
the number says little about ATBP itself. We therefore judge recovery by
what it adds to the same model and pipeline, on both clean and
fault-injected traces, rather than by an absolute accuracy figure.

\subsection{Research Questions}

The gaps lead to three questions.

\begin{itemize}
    \item \textbf{RQ1.} Can verification confidence, dependency depth,
    downstream impact, and estimated cost select a recovery scope that
    is more accurate or cheaper than any fixed scope?
    \item \textbf{RQ2.} Under controlled claim-level faults, how do the
    four recovery scopes differ in error cascade, repair success, and
    collateral damage?
    \item \textbf{RQ3.} Do these differences, and the accuracy target,
    hold with stronger models and with token usage and latency
    included?
\end{itemize}

\subsection{Changes to the Dataset}

We did not edit, filter, relabel, or add any problem. The only
processing is reading the gold answer: we take the text after
\texttt{\#\#\#\#}, remove thousands separators (14 test answers contain
them), and parse the result as a number. The models only ever see the
\texttt{question} field. The reference solution and its calculator
annotations are used for scoring and are never shown to any agent.

\subsection{Data Produced by the Pipeline}

Two kinds of records are created while the systems run, and both are
stored with every result. The first is the claim list of each Agent A
plan. Each claim has an identifier, its text, and the identifiers of the
earlier claims it uses (Section~\ref{sec:method}). The second is one
record per injected fault, whose fields are listed in
Table~\ref{tab:injfields} with a real example. The reference answer of
the problem stays the clean one, so every recovery strategy starts from
the same corrupted trace and is scored against the same answer.
Section~\ref{sec:injection} explains how the faults are made.

\section{System Architecture}
\label{sec:architecture}

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth,height=0.4\textheight,
keepaspectratio]{visual_architecture.png}
\caption{ATBP architecture. A verification and recovery layer sits
between Agent A and Agent B.}
\label{fig:architecture}
\end{figure*}

The system is a sequential pipeline of three LLM agents:
\[
\text{Problem} \rightarrow A \rightarrow B \rightarrow C
\rightarrow \hat{y}.
\]
Agent A writes a step-by-step plan. Agent B checks that plan and
continues the reasoning, and Agent C writes the final answer in a fixed
format from which the number is read. The baseline
(Fig.~\ref{fig:baseline}) is this pipeline and nothing else.

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth,height=0.4\textheight,
keepaspectratio]{baseline_architecture.png}
\caption{Baseline sequential multi-agent reasoning architecture.}
\label{fig:baseline}
\end{figure}

The recovery architecture (Fig.~\ref{fig:architecture}) places a
verification and recovery layer between Agent A and Agent B. The layer
has four parts.

\begin{enumerate}
    \item \textbf{Claim extractor.} Splits Agent A's plan into atomic
    claims and records which earlier claims each one uses.
    \item \textbf{Dependency graph.} Built from those links. It gives the
    dependents, ancestors, and depth of any claim.
    \item \textbf{Hybrid verifier.} Runs a deterministic arithmetic check
    and a grounding check on every claim, and sends the remaining claims
    to an LLM judge in one batched call.
    \item \textbf{Recovery controller.} If any claim fails, it chooses one
    of four scopes and applies it: isolated claim repair, branch
    backtracking, agent-level regeneration (a new plan written with the
    failed steps as feedback), or full regeneration (a new plan sampled
    without feedback).
\end{enumerate}

Whatever the controller does, the resulting plan then goes through
Agents B and C exactly as in the baseline. All systems produce their
final answer the same way, so a difference between two systems can only
come from the plan that reaches Agent B.

Two further design choices keep the comparison fair. First, every system
starts from the same first plan. Agent A's initial plan, its claims, and
their verification are generated once with greedy decoding and then
reused through a cache of model calls, so a system can differ from the
baseline only through its recovery decision. Second, every model call
goes through one client that records prompt tokens, completion tokens,
and model time. Calls answered from the cache are charged at their
original cost, so the reported cost of a system does not depend on the
order in which systems were run.

% ============================================================
% 5. METHODOLOGY
% ============================================================
\section{Methodology}
\label{sec:method}

The method has six parts: sequential reasoning, claim extraction,
dependency modeling, claim verification, recovery, and the controlled
fault injection used to evaluate recovery.

\subsection{Sequential Multi-Agent Reasoning}

Let $P$ be the input problem. The baseline pipeline is
\[
P \rightarrow A \rightarrow B \rightarrow C \rightarrow \hat{y},
\]
where $A$, $B$, and $C$ are the three agents and $\hat{y}$ is the
predicted answer. Final-answer accuracy is
\[
\mathrm{Accuracy} = \frac{N_{\mathrm{correct}}}{N},
\]
where $N_{\mathrm{correct}}$ is the number of correctly solved examples
and $N$ is the number evaluated.

\subsection{Atomic Claim Extraction}

Agent A produces a reasoning sequence
\[
R_A = \{s_1,s_2,\ldots,s_m\},
\]
which the system converts into a set of atomic claims
\[
C = \{c_1,c_2,\ldots,c_n\}.
\]
Each claim is a triple
\[
c_i = (id_i,text_i,D_i),
\]
where $id_i$ is the identifier, $text_i$ is the content, and $D_i$ is
the set of prerequisite claims that $c_i$ depends on.

The extractor is an LLM prompted to copy each step with its numbers and
calculations exactly as written, without fixing anything. Its output is
constrained by a JSON schema through OpenAI's strict structured outputs.
The result is then normalized: claims are renumbered $c_1,\ldots,c_n$ in
reasoning order, and only links to earlier claims are kept. The graph is
therefore acyclic by construction, and the reasoning order is also a
topological order. Recovery depends on these links, since a missing or
wrong edge gives a wrong recovery boundary. We have not yet measured
extraction quality against human labels.

\subsection{Dependency Graph}

The claims form a directed graph $G=(V,E)$, where each vertex
$v_i \in V$ is a claim and an edge $(c_i,c_j)\in E$ means that $c_j$
depends on $c_i$:
\[
(c_i,c_j)\in E
\quad \Longleftrightarrow \quad
c_i \in D_j.
\]
The downstream set of a claim $c$ is
\[
\operatorname{Down}(c)=
\{v\in V\mid c\leadsto v\},
\]
where $c\leadsto v$ means a directed path exists from $c$ to $v$, and
$\operatorname{Up}(c)$ is defined in the same way for ancestors. The
dependency depth is
\[
d(c)=
\begin{cases}
0, & \text{if } Pred(c)=\emptyset,\\[4pt]
1+\max_{p\in Pred(c)}d(p), & \text{otherwise.}
\end{cases}
\]

A downstream claim is a candidate for rechecking, not a proven error. It
may have been derived independently, or it may still be correct after an
upstream mistake.

\subsection{Claim Verification}

Each claim passes through up to three checks.

\begin{enumerate}
    \item \textbf{Arithmetic check.} Every equation in the claim, such as
    ``$9 \times 60 = 540$'', is parsed after LaTeX and Unicode symbols are
    normalized, and is evaluated exactly. Percentages and chained
    equalities are handled. A result that differs from the true value by
    more than rounding marks the claim invalid with confidence 1, and the
    correct value is stored for the repair step.
    \item \textbf{Grounding check.} Every operand of a calculation must
    appear in the problem (number words included), in an earlier claim,
    or in a short list of common constants such as 12, 24, 60, or 100. A
    claim that uses an unexplained number is marked invalid with
    confidence 0.85.
    \item \textbf{LLM judge.} The claims not settled by the first two
    checks are sent with the problem in a single call. The judge is told
    that the arithmetic has already been checked and is asked whether the
    right quantities and operations are used. It returns a label, a
    confidence, and a short rationale for each claim. A claim that the
    batched call misses is judged on its own.
\end{enumerate}

The verifier therefore returns, for each claim,
\[
V(c_i)=(\mathrm{valid}_i,q_i),
\]
where $q_i\in[0,1]$. A threshold $\tau$ decides acceptance:
\[
\mathrm{Accepted}(c_i)=
\begin{cases}
1, & \mathrm{valid}_i=\mathrm{True}
\land q_i\geq\tau,\\
0, & \text{otherwise,}
\end{cases}
\]
with $\tau=0.80$.

The deterministic checks cannot be fooled by the model, but they only
catch arithmetic and copying errors. The judge covers everything else,
but it runs on the same model as the agents. Its confidence is a
model-generated estimate rather than a calibrated probability, and its
mistakes may line up with the agents' mistakes.

\subsection{Recovery Scopes}

When at least one claim fails,
\[
\exists c_i\in C:\ \mathrm{Accepted}(c_i)=0,
\]
one of four recovery scopes is applied. After any scope, the new plan is
verified again.

\paragraph*{Isolated claim repair ($R_{\mathrm{claim}}$).} Each failed
claim is repaired on its own. If the arithmetic check rejected it, the
stored correct value is written in directly. Otherwise an LLM rewrites
only that step, given the problem, the earlier steps, and the verifier's
rationale. Dependent claims are left as they are, even if they used the
wrong value.

\paragraph*{Branch backtracking ($R_{\mathrm{branch}}$).} The failed
claims and all claims in their downstream sets are recomputed in
reasoning order. Failed claims are repaired as above. For each dependent
claim, if a corrected value appears in it exactly once, the new value is
substituted and the arithmetic is recomputed. If the value is missing or
ambiguous, for example when the same number appears twice, an LLM
re-derives the claim from its corrected prerequisites. Claims outside the
branch are not touched.

\paragraph*{Agent-level regeneration ($R_{\mathrm{agent}}$).} Agent A
writes a new plan, and the prompt lists the failed steps and why they
failed. Sampling uses temperature 0.7, with a different seed for each of
up to three attempts. The first plan whose claims all pass is kept. If
none passes, the attempt with the fewest failed claims is kept.

\paragraph*{Full regeneration ($R_{\mathrm{full}}$).} The same procedure
without any feedback, which amounts to a blind restart of Agent A.

The fixed-scope systems always use one action: A2 uses full
regeneration and A3 uses isolated repair. A4 is ATBP, which chooses the
scope as described next.

\subsection{Adaptive Recovery Scope}

ATBP treats recovery as a choice from the action set
\[
\mathcal{R} =
\{R_{\mathrm{claim}},R_{\mathrm{agent}},
R_{\mathrm{branch}},R_{\mathrm{full}}\}.
\]
For each failed claim $c_f$ the system computes the features
\[
x_f =
[q_f,d(c_f),|\operatorname{Down}(c_f)|,
|\operatorname{Up}(c_f)|,\mathrm{cost}_f],
\]
where $q_f$ is the verifier confidence, $d(c_f)$ the dependency depth,
$|\operatorname{Down}(c_f)|$ and $|\operatorname{Up}(c_f)|$ the numbers
of downstream and upstream claims, and
$\mathrm{cost}_f = (1+|\operatorname{Down}(c_f)|)/n$ the share of the
plan that a branch repair would touch. A policy $\pi$ maps these
features to an action, $R^*=\pi(x_f)$.

The current policy is a short list of rules
(Algorithm~\ref{alg:policy}). If most of the plan failed, the plan is
treated as broken and fully regenerated. If there are several
independent faults, Agent A is asked for a new plan with feedback. If no
failed claim has dependents, only the failed claims are repaired.
Otherwise the failed branch is recomputed, unless that branch would cover
most of the plan, in which case regenerating with feedback is the
simpler option. The confidence $q_f$ enters only through the acceptance
threshold. The two thresholds were fixed by hand before the experiments
and have not been tuned.

\begin{algorithm}[t]
\caption{Rule-based scope selection in A4}
\label{alg:policy}
\begin{algorithmic}[1]
\Require claims $C$ ($|C|=n$), failed set $F$, graph $G$
\If{$F=\emptyset$} \Return no recovery \EndIf
\State $A \gets F \cup \bigcup_{c\in F}\operatorname{Down}(c)$
\State $k \gets |\{c\in F : \operatorname{Up}(c)\cap F=\emptyset\}|$
\If{$|F|/n \geq 0.5$} \Return $R_{\mathrm{full}}$ \EndIf
\If{$k \geq 3$} \Return $R_{\mathrm{agent}}$ \EndIf
\If{$\operatorname{Down}(c)=\emptyset$ for all $c\in F$}
  \Return $R_{\mathrm{claim}}$ \EndIf
\If{$|A|/n \geq 0.6$} \Return $R_{\mathrm{agent}}$ \EndIf
\State \Return $R_{\mathrm{branch}}$
\end{algorithmic}
\end{algorithm}

Our hypothesis is that these features give a better balance of
correctness, collateral change, and cost than any fixed scope. The graph
alone cannot guarantee a good choice, because both the verifier and the
extracted links can be wrong, so the hypothesis is tested on inputs with
known fault locations.

\subsection{Controlled Fault Injection}
\label{sec:injection}

To test recovery when the error is known, we corrupt one claim in a
clean trace. There are two fault types.

\begin{itemize}
    \item \textbf{Arithmetic fault.} The result of a correct calculation
    is replaced by a plausible wrong value, for example
    ``$0.6\times 5=6$'' instead of 3.
    \item \textbf{Operand fault.} A number copied from the problem is
    replaced by a wrong value and the result is recomputed, so the
    arithmetic itself stays consistent, for example ``$3\times 18=54$''
    when the problem says 15.
\end{itemize}

Wrong values come from a seeded random generator that applies a small
offset or a factor such as 0.5, 1.25, or 2. Each fault is placed in one
of two positions: \emph{deep}, the eligible claim with the most
dependents, or \emph{leaf}, an eligible claim with no dependents. The
wrong value is then carried into every downstream claim with correct
arithmetic. Only the target claim is wrong, and every later claim that
uses it is consistently wrong, which is what a real early mistake looks
like. A problem is used only if the clean pipeline solves it, because
otherwise a recovered answer could not be told apart from one that was
never corrected.

Each corrupted trace is run under two localization conditions. Under
\emph{detected} localization the hybrid verifier decides which claims
failed. Under \emph{oracle} localization exactly the injected claim is
marked as faulty, which separates the quality of recovery from the
quality of detection. Under each condition we run no recovery, each of
the four fixed scopes, and the A4 policy, all from the same corrupted
trace.

\subsection{Verifier Refinements}
\label{sec:v2}

The first runs showed that most flags on correct plans came from the LLM
judge, and that some of its rationales contradicted themselves. We
therefore added three optional changes. They are switched on together,
and we refer to this configuration as V2.

\begin{enumerate}
    \item \textbf{Value check.} The judge must also state the value an
    invalid claim should have. If that value equals the value the claim
    already states, the flag is dropped. This removes cases such as a
    judge rejecting ``$204+160+330=694$'' while giving 694 as the correct
    total.
    \item \textbf{Program cross-check.} Following program-aided reasoning
    \cite{pal}, the model writes a short Python program that solves the
    problem from scratch. The program runs in a separate interpreter with
    a time limit, and only plain arithmetic code is allowed. If its
    answer matches the value of the plan's final claim, flags raised only
    by the judge are dropped. If it disagrees, one more call names the
    first wrong step, which is flagged with the program's answer as
    evidence for the repair. A program that fails, or a plan whose last
    step states no value, gives no signal.
    \item \textbf{Do-no-harm rule.} If the recovered plan still fails
    verification, the original plan is passed to Agent B instead.
\end{enumerate}

\section{Experimental Setup}
\label{sec:setup}

\paragraph*{Model.} All experiments use GPT-4o-mini through the OpenAI
API (snapshot \texttt{gpt-4o-mini-2024-07-18}). The same model plays
every role: the three agents, the claim extractor, the LLM judge, and
the repair prompts.

\paragraph*{Decoding.} The initial plan and all extraction,
verification, and repair calls use temperature 0 and a fixed seed.
Regeneration uses temperature 0.7 with a different seed for each attempt,
because repeating a zero-temperature prompt tends to reproduce the
rejected plan. Each call may generate at most 2048 tokens, the
acceptance threshold is $\tau=0.80$, and a regeneration scope makes at
most three attempts. The API treats the seed as best-effort, so every
call and its token counts are stored, and the reported runs can be
replayed exactly from these records.

\paragraph*{Evaluated problems.} Each problem needs between 3 and about
20 model calls depending on the system, so for this study we evaluate a
fixed slice of the test split rather than all 1,319 problems. The
natural-error runs use the first 30 test problems (indices 0--29). The
fault-injection runs use the first eight (indices 0--7). Of those, one
was dropped because the clean pipeline answered it wrongly, and one had
no claim suitable for injection. One planned operand fault could not be
placed because its operand could not be located unambiguously in the
claim. This left 16
faults in six problems.

\paragraph*{Systems.} Table~\ref{tab:systems} lists the systems. All of
them run on the natural-error set. The fault-injection experiment adds
the fixed scopes as separate conditions. We also ran the natural-error
set with the V2 verifier (Section~\ref{sec:v2}), and once with a
shortened Agent B prompt to test whether tokens could be saved without
losing accuracy.

% 7. EVALUATION METRICS
% ============================================================
\section{Evaluation Metrics}
\label{sec:metrics}

The primary metric is final-answer accuracy,
\[
\mathrm{Accuracy}=\frac{N_{\mathrm{correct}}}{N}.
\]
The metrics below describe recovery and its cost.

\subsection{Error Cascade Rate}

ECR is the share of examples with a detected intermediate fault that end
with an incorrect answer:
\[
\mathrm{ECR}=
\frac{N_{\mathrm{incorrect\ final\ answers\ after\ detection}}}
{N_{\mathrm{examples\ with\ detected\ faults}}}.
\]
It is computed over examples in which initial verification rejected at
least one claim. It measures association, not cause, because a detected
fault may be a false alarm and downstream agents can add new errors. The
fault-injection experiment is what estimates the effect of a known fault.

\subsection{Repair Success Rate}

RSR is the share of recovery actions that the verifier accepts on
re-checking:
\[
\mathrm{RSR}=
\frac{N_{\mathrm{successful\ recovery\ actions}}}
{N_{\mathrm{recovery\ attempts}}}.
\]
Under claim-level recovery each repaired claim is one attempt. Under
branch backtracking each recomputed claim is one attempt, and under
regeneration each sampled plan is one attempt. An attempt succeeds when
the affected claims pass re-verification. Because the unit differs
between scopes, RSR values should be read together with the type of
action. RSR measures acceptance by the verifier, not confirmed
correctness.

\subsection{Collateral Damage Rate}

CDR is the share of previously accepted claims exposed to recovery that
are discarded or rewritten:
\[
\mathrm{CDR}=
\frac{N_{\mathrm{previously\ accepted\ claims\ altered}}}
{N_{\mathrm{previously\ accepted\ claims\ exposed\ to\ recovery}}}.
\]
Under regeneration every accepted claim in the replaced plan counts as
discarded. Under targeted repair an accepted claim counts only if the
recovery rewrites it. CDR measures how much accepted reasoning changed,
not whether the changes were wrong.

\subsection{Token Usage and Model Time}

Token usage is the mean number of prompt plus completion tokens per
problem, summed over every call made by the agents, the claim extractor,
the verifier, and recovery. Model time is the sum of the durations of
those calls,
\[
\overline{T}=\frac{1}{N}\sum_{i=1}^{N}T_i,
\]
where $T_i$ is the model time for example $i$. We report model time
rather than wall-clock time, because the cache and parallel execution
make wall-clock time depend on how the runs were scheduled.

\subsection{Scope Agreement}

In the fault-injection experiment every scope is run on every case, so
we can see which scopes reach the correct answer. Scope agreement is the
share of cases in which A4 chose the recovery scope that reached the
correct answer with the fewest tokens. It shows how close the policy
comes to the best choice available in hindsight.

whose ``correct'' value matched the stated one, and agreement with the
program dropped 9 more. The program produced an answer for 27 of the 30
problems and was right on 25 of them. It was wrong on one problem where
the plan was right. There it flagged the correct plan, the repair did
not pass re-verification, and the do-no-harm rule passed the original
plan on, so the answer stayed correct. It did not help with the two
misreadings. On the download problem the program made the same misreading
as the plan, and on the lemon-tree problem its loop never ended, so it
gave no answer.

Shortening Agent B's prompt cut the baseline's cost by 36\% (from 2168
to 1383 tokens per problem) but cost one problem. In that problem
Agent A had misread a percentage increase. The full Agent B, which
re-derives the solution, had corrected it, and the shortened one
``corrected'' it to another wrong value. The extra tokens Agent B spends
are part of why the baseline is hard to beat, so we kept the full prompt.

% ============================================================
% 9. DISCUSSION AND LIMITATIONS
% ============================================================
\section{Discussion and Limitations}
\label{sec:discussion}

The results separate two questions that are easy to blur: whether a
system can repair an error once it knows where the error is, and whether
the error matters by the time the final answer is written.

On the first question the results are encouraging. The verifier found
every injected fault, and every recovery scope except agent-level
regeneration repaired all of them. ATBP did so with fewer tokens than
full regeneration and rewrote far less of the accepted reasoning.
Regeneration with feedback, which sounds like the more careful option,
was the least reliable, because a rewritten plan can go wrong somewhere
new. This supports the main idea behind ATBP, that recovery should
touch as little of the plan as it needs to.

On the second question the picture is different. With GPT-4o-mini the
later agents already absorb most errors. Agent B re-derives the
solution, and in the injection experiment it corrected all 16 faults
with no recovery at all. The short Agent B prompt showed the same thing
from the other side, because removing that re-derivation cost a problem.
The errors that survive to the final answer are misreadings of the
question, and the verifier rarely detects them. The arithmetic checks
cannot see them, the judge shares the agents' blind spots, and even an
independent program made the same misreading in one case. The value and
program checks in V2 halved the false alarms, and the do-no-harm rule
stopped a wrong flag from breaking a correct answer.

For the research questions this means the following. RQ2 is partly
answered: the scopes differ clearly in collateral change and cost, and
agent-level regeneration repairs less reliably. RQ1 remains open. ATBP
matched the best fixed scopes on accuracy, but in our cases isolated
repair was always enough, and the policy often chose a broader scope
than needed. RQ3 is answered only for one model. A stronger backbone
leaves recovery little room to improve the final answer.

The study has the following limitations.
\begin{enumerate}
    \item The samples are small: 30 problems for natural errors and 16
    injected faults on six problems, all from the start of the test
    split.
    \item Only one model was evaluated.
    \item The injected faults were shallow, with at most four
    dependents, and the downstream agents corrected all of them without
    help.
    \item The same model generates, extracts, and judges, so its errors
    may be correlated. Only the arithmetic and grounding checks are
    independent of the model.
    \item The policy thresholds were set by hand, the confidence feature
    is used only through the acceptance threshold, and the failure-rate
    rule counts every flagged claim as a separate fault, even when the
    flags come from one upstream error.
    \item Claim extraction and dependency links have not been checked
    against human labels.
    \item CDR counts changed claims but does not check whether the
    changes were correct.
\end{enumerate}

The next stage follows from these results. It will cover more of the
test split, including problems on which the baseline fails, so that a
better system has room to show it. It will inject faults that the later
agents cannot absorb as easily, such as several faults per trace, faults
in long dependency chains, and misreadings of the question. It will also
count inherited errors as one fault when the policy measures how much of
the plan has failed. The oracle runs already record which scope was
cheapest in each case, and we plan to learn the scope policy from these
records instead of setting the thresholds by hand.

% ============================================================
% 10. CONCLUSION
% ============================================================
\section{Conclusion}
\label{sec:conclusion}

This paper presents ATBP, a recovery-scope selection method for
sequential multi-agent reasoning. It splits intermediate reasoning into
atomic claims, links them in a dependency graph, checks them with a
hybrid verifier, and chooses among isolated claim repair,
dependency-aware branch backtracking, agent-level regeneration, and full
regeneration. Prior rollback, verification, and correction methods each
cover part of this problem, but none we found chooses the recovery scope
from claim dependencies.

With GPT-4o-mini, the verifier found all 16 injected faults, and ATBP
repaired every case with 19--26\% fewer tokens than full regeneration
while rewriting much less of the accepted reasoning. On unmodified GSM8K
problems recovery did not change accuracy, and every system reached
93.3\%. The later agents already corrected the injected faults on their
own, and the errors that remained were misreadings of the question that
the verifier did not detect.

Targeted repair works when the error is found. The harder problems are
finding the errors that matter and testing recovery on faults the rest
of the pipeline cannot absorb. The next stage therefore concentrates on
detection, harder and deeper faults, a larger part of the test split,
and a learned scope policy.
